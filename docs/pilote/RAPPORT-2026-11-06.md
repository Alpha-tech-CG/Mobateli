# Pilote CodeGate sur trois projets d'Alpha — 6 novembre 2026

Ce pilote mesure CodeGate sur du vrai code d'Alpha, pas sur des applications
vulnérables écrites pour l'occasion. Les trois dépôts ont été **lus
seulement** : rien n'y a été modifié ni poussé.

| Projet | Dossier analysé | Dépôt |
|---|---|---|
| Alpha Kelassi | `D:\alpha-kelassi-new` | `mastefox2742/alpha-kelassi` |
| Alpha Pay | `D:\Alphapay` | `Alpha-tech-CG/Alpha_pay` |
| Académie | `D:\site web alpha\alpha-academie\alpha-academy-labs`, **sans `alphavuln/` ni `solutions/`** | `Alpha-tech-CG/intra-alpha-academie` |

**Académie : périmètre confirmé par l'utilisateur.** On analyse le dépôt de la
plateforme, `alpha-academy-labs` : portail Next.js, orchestrateur de labs,
AlphaSOC, AlphaForensics et AlphaCTFd.

`alphavuln/` et `solutions/` sont **exclus** des chiffres de l'académie, car
ils sont vulnérables exprès. Ce sont des cibles d'entraînement et des supports
de cours. Ils sont retirés avec l'option `--exclude alphavuln,solutions` du
runner, sans rien écrire dans le dépôt.

Les machines `docker/alpha-machine-*` sont aussi des cibles d'entraînement. Hors
de ces deux dossiers, elles restent dans le compte et sont signalées comme
telles : elles portent 1 alerte, vraie.

Le dossier `intraAlphalab`, d'abord indiqué, ne contient que la documentation
et une vidéo : 10 fichiers, 0 alerte.

Les cibles exclues servent quand même à une **mesure de rappel à part**, à la
fin du rapport. Elle ne compte pas dans les chiffres de l'académie.

## Méthode

- **Analyse.** `node --import tsx bench/juiceshop.ts <dossier> --rust
  --per-file` simule une PR par fichier, comme le bot, avec les moteurs core
  et rust.
- **Fichiers pris en compte.** Le runner lit désormais les **fichiers suivis
  par git** (`git ls-files`), c'est-à-dire ce qu'une PR peut contenir. Les
  `.next`, `.turbo`, `.pnpm-store` et autres dossiers locaux sont donc exclus.
  Il respecte aussi `.codegateignore` ; aucun des trois projets n'en a.
- **Secrets hors code.** Le Secret Shield a été passé aussi sur **tous** les
  fichiers texte suivis (YAML, Dockerfile, Markdown, JSON…). Le bot les lit
  dans une PR, alors que le runner ne lit que le code.
- **Tri.** Chaque alerte a été triée à la main en lisant le code autour :
  **V** (vraie), **D** (discutable) ou **F** (fausse).
- **Précision.** Elle vaut V / (V + F) ; les alertes discutables sont exclues
  du calcul. Elle est mesurée deux fois : sur toutes les alertes, puis sur
  celles qui pèsent sur le verdict (confiance moyenne ou haute). Depuis la
  PR #9, une alerte en confiance basse est listée « à vérifier » sans changer
  le verdict.
- **À l'aveugle d'abord.** Les chiffres « à l'aveugle » ont été mesurés
  **avant** toute correction. Les chiffres « après » sont ceux de la branche
  de ce rapport.
- **Langages.** Les trois projets sont en JS/TS (Next.js, NestJS, Expo, Vite)
  avec un peu de Python : aucun autre langage hors du périmètre. Les 90
  migrations SQL de Kelassi (politiques RLS Supabase) ne sont pas lues par
  CodeGate.

## Corrections apportées dans cette PR (causes générales)

1. **Templates SQL balisés** (`SQL_STRING_CONCAT`).
   - **Ce qui ne déclenche plus.** Les `${…}` de Prisma `` $queryRaw`…` `` /
     `` $executeRaw`…` `` et d'un tag `` sql`…` `` (drizzle, postgres.js,
     slonik, `Prisma.sql`) sont des paramètres liés, y compris sur plusieurs
     lignes : on suit le template jusqu'à son backtick fermant.
   - **Ce qui reste signalé.** `$queryRawUnsafe`, `sql.raw(…)`/`unsafe(…)`
     glissés dans le template, ou une concaténation de chaînes sur la ligne.
   - **Effet.** 19 fausses alertes en moins.
2. **innerHTML et `dangerouslySetInnerHTML` sans entrée** (`XSS_INNERHTML`).
   - **Ce qui ne déclenche plus.**
     - une constante MAJUSCULE du module (`HTML`, `ICONS[name]`) ;
     - un littéral ou template sans `${`, y compris quand `__html:` est sur la
       ligne suivante ;
     - la copie du `innerHTML` d'un autre élément.
   - **Détails.** Chaque affectation d'une même ligne est évaluée, et un
     littéral contenant `;` (`'&times;'`) reste reconnu.
   - **Effet.** 44 fausses alertes en moins.
3. **Réponses non HTML** (moteur Rust, `RUST-JS-XSS-TAINT`). Un `res.send` est
   ignoré quand la fonction déclare l'une de ces choses :
   - un `Content-Type` littéral non HTML (`application/pdf`, `text/csv`,
     `res.type('json')`…) ;
   - un `Content-Disposition: attachment` ou un `res.attachment(…)` ;
   - une CSP `sandbox` sans `allow-scripts`.

   HTML, XML et SVG restent signalés, ainsi que les gestionnaires voisins.
   **Effet.** 7 fausses alertes en moins.
4. **`res.download` seulement** (moteur Rust, PATH). Le puits `.download` ne
   s'applique plus à n'importe quelle méthode `download()` d'un service, mais
   seulement à `res.download` / `response.download`. **Effet.** 1 fausse
   alerte en moins.
5. **Secrets.**
   - **Valeurs écartées.** Une valeur tronquée (`…`, `...`) ou une phrase
     (libellé d'interface) n'est plus un secret.
   - **URL de base de données.** Vers `localhost`, `127.*`, un service compose
     (hôte sans point) ou avec des parties gabarits (`${…}`, `USER:PASS@HOST`),
     elle passe en confiance basse.
   - **Effet.** 2 fausses alertes de code en moins, et 22 secrets hors code
     qui ne bloquent plus.
6. **`WEAK_RANDOM` en confiance moyenne pour un identifiant.** Quand la
   fonction ou la variable désigne un mot de passe, un jeton, un OTP ou un
   `clientSecret`, la confiance devient moyenne. Un `key` ou un `secret` seuls
   restent en confiance basse. **Effet.** Les 2 mots de passe temporaires de
   l'académie pèsent désormais sur le verdict.
7. **Runner `bench/juiceshop.ts`.**
   - Il lit les fichiers suivis par git ; si l'index est vide (une copie de
     travail qui a échoué), il revient au parcours du dossier.
   - Il respecte `.codegateignore`.
   - L'option `--exclude dir1,dir2` retire des dossiers sans écrire dans le
     dépôt analysé (ici, les cibles volontaires de l'académie).

- **Benchmark golden** (`--engines core,rust --check`). Sans régression : 97 %

- **Benchmark holdout.** Sans régression : 96 % / 98 %. Au niveau verdict, le
  rappel passe de 89 % à **91 %**.
- **Tests.** `pnpm --filter @codegate/api test` : 106/106. `cargo test
  --release` : tout passe, avec 3 nouveaux tests d'intégration. `cargo clippy

## Corrections recommandées, non faites ici (par priorité)

1. **Puits sqlite** (`db.all/get/run/each/exec/prepare`) dans le moteur Rust.
   Il faudrait un argument qui ressemble à du SQL, pour ne pas confondre avec
   `Promise.all`, `map.get` ou un `db.get(key)` clé-valeur. Cela ferait passer
   les 5 SQLi d'`alphavuln` en confiance moyenne. Risque moyen : à faire avec
   un test dédié sur code propre.
2. **Next.js App Router.**
   - **Ce qu'il faut modéliser.** La source `new URL(request.url).searchParams`
     / `request.nextUrl.searchParams` et le puits `NextResponse.redirect`.
   - **La difficulté.** `origin` vient de la même URL et préfixe presque toutes
     les redirections légitimes (`${origin}/login`). Il faut distinguer
     `${origin}${next}`, dangereux, de `${origin}/chemin`, sûr.
   - **Effet attendu.** Attraperait la redirection ouverte de l'académie.
3. **Motifs de secrets par dépôt.** Une configuration pour les formats maison
   (`ap_live_…` d'Alpha Pay).
4. **Sources Python `http.server`.** `self.path` est trop commun hors HTTP ; il
   faudrait le limiter aux classes qui héritent de `BaseHTTPRequestHandler`.
   **Puits Flask.** Le retour d'une vue (`return "…" + arg`). Ensemble, ils
   rattraperaient 3 failles volontaires ratées.
5. **SSRF de second ordre.** Une URL lue en base puis appelée (webhooks
   sortants). C'est hors de portée du suivi de taint actuel ; une règle de
   revue pourrait signaler un `fetch(endpoint.url)` sans contrôle de
   résolution ou de redirection.
6. **Bruit résiduel en confiance basse.**
   - `WEAK_RANDOM` sur `key` (clés de tri, d'idempotence) ;
   - `WEAK_HASH` sur une chaîne de texte ;
   - les constantes camelCase ou passées par une variable locale
     (`themeScript`, `PATHS[name]`) ;
   - les templates multilignes fixes.

   Ces cas demandent de suivre les constantes du fichier ; le gain est faible
   tant qu'ils restent en confiance basse.
